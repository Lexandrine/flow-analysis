# Реестр требований: связываем обещание и доказательство

| ID / требование | Источник / приоритет | Проверка | Статус |
|---|---|---|---|
| **F-01:** автоматически выгружать сырые почасовые данные (скорость, интервалы, класс ТС) по ID объекта и заданному периоду времени | Заказчик / обязательно | Запрос к БД «ВостокМ»; сверка объёма и полноты выгрузки с эталоном | Запланировано |
| **F-02:** обогащать данные контекстными признаками (время суток, день недели, доля грузового транспорта, погодные условия) | Аналитик / обязательно | Unit-тесты на тестовой выборке; проверка наличия всех признаков в итоговом датасете | Запланировано |
| **F-03:** выполнять ML-скоринг каждой аномалии — присваивать вероятность ложного срабатывания (0–100%) | Аналитик / обязательно | Сравнение прогнозов модели с экспертной разметкой на выборке из 100+ аномалий; расчёт F1-score | Запланировано |
| **F-04:** применять контекстную фильтрацию — автоматически отсеивать аномалии, объяснимые суточными/недельными паттернами или погодой | Заказчик / обязательно | A/B-тест: доля ложных срабатываний до и после применения фильтра на исторических данных за 3 месяца | Запланировано |
| **F-05:** предоставлять интерфейс экспертной разметки — инженер одним кликом помечает аномалию как «истинную» или «ложную» с указанием причины | Пользователь / обязательно | Юзабилити-тест с 2–3 инженерами; замер времени разметки одной аномалии | Запланировано |
| **F-06:** генерировать итоговый отчёт (CSV/PDF) со списком объектов, где алгоритм компании систематически ошибается, и рекомендациями по корректировке порогов | Заказчик / обязательно | Ручная проверка отчёта на соответствие шаблону; валидация рекомендаций экспертом | Запланировано |
| **F-07:** обеспечивать адаптивную калибровку — пересчёт базовых порогов для конкретного объекта на основе накопленной экспертной разметки | Аналитик / желательно | Замер изменения F1-score модели до и после калибровки на отложенной выборке | Запланировано |
| **NF-01:** соблюдать порог времени обработки — анализ выборки из 1000 аномалий не должен занимать более 5 минут | Производительность / обязательно | Замеры при заданной нагрузке на тестовом стенде | Запланировано |
| **NF-02:** обеспечивать безопасность данных — все действия логируются, доступ только по временным учётным записям, данные не покидают периметр КИИ | Безопасность / обязательно | Аудит логов; проверка прав доступа; penetration-тест | Запланировано |
| **NF-03:** достигнуть точности ML-модели — F1-score ≥ 0.80 на валидационной выборке | Качество / обязательно | Кросс-валидация на исторических данных за 6 месяцев | Запланировано |
| **NF-04:** обеспечивать масштабируемость — решение должно работать на всех ~2000 объектах заказчика без деградации производительности | Масштабируемость / желательно | Стресс-тест на увеличивающейся выборке (100 → 1000 → 10000 объектов) | Запланировано |
| **NF-05:** обеспечивать надёжность — система должна корректно обрабатывать пропуски в данных (сбои датчиков, рассинхрон по времени) без критических ошибок | Надёжность / обязательно | Инъекция пропусков в тестовые данные; проверка graceful degradation | Запланировано |

---

## Легенда статусов

| Статус | Значение |
|---|---|
| **Запланировано** | Требование зафиксировано, разработка ещё не начата |
| **В работе** | Требование находится в активной разработке |
| **Реализовано, не проверено** | Функция разработана, но тестирование ещё не проведено |
| **Реализовано, проверено** | Функция разработана и успешно прошла тестирование |

## Приоритеты требований

| Приоритет | Описание | Примеры из реестра |
|---|---|---|
| **Обязательно** | Критичные требования, без которых решение теряет смысл или не может быть принято заказчиком | F-01, F-02, F-03, F-04, F-06, NF-01, NF-02, NF-03 |
| **Желательно** | Важные требования, улучшающие качество решения, но не блокирующие его запуск | F-05, F-07, NF-04, NF-05 |

---

**Примечание:** Все требования находятся на этапе планирования. Статусы будут обновляться по мере реализации проекта. Формулировки сокращены для наглядности. В рабочем реестре — полные условия и ссылки на доказательства (протоколы тестирования, скриншоты, метрики).
