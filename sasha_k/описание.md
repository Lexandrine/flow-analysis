# Анализатор аномалий трафика А-134 «Подъезд к Воронежу»

## 📋 Цель проекта

Автоматизированное выявление аномалий в почасовых данных об интенсивности движения на участке **км 8+100 а/д А-134** за период 3 года (2023–2026). Система не только находит отклонения, но и **объясняет их причины** через поиск новостей и кластеризацию паттернов.

## 📦 Модули кода

### 1. Парсер данных (`parse_traffic_excel`)

**Задача:** Извлечь структурированные данные из сырых Excel-отчетов Росавтодора.

**Ключевые особенности:**
- Потоковое чтение через `openpyxl.read_only=True` (экономия памяти)
- Автоматическое распознавание участка дороги по regex `км\s*\d+(\+\d+)?`
- Пропуск служебных строк («Итого», «Среднее», «%»)
- Нормализация чисел (замена неразрывных пробелов `\xa0`, запятых → точки)
- Обработка 29 колонок: интенсивность по 7 классам ТС × 3 направления + скорость + загрузка

**Структура данных:**

| Колонка | Описание |
|---------|----------|
| `road_section` | Участок дороги (км 8+100) |
| `timestamp` | Дата и время (почасовая гранулярность) |
| `vol_total/direct/reverse` | Общая интенсивность (итого/прямое/обратное) |
| `cars_total`, `small_trucks_total`, ... | Интенсивность по 7 классам ТС |
| `speed_direct/reverse` | Скорость, км/ч |
| `load_direct/reverse` | Загрузка, % |

---

### 2. ML-кластеризация (`cluster_daily_profiles`)

**Задача:** Автоматически выделить типы дней без ручной разметки.

**Алгоритм:**
1. Построение матрицы `дни × 24 часа` из `vol_total`
2. Фильтрация неполных дней (< 20 часов)
3. Нормализация через `StandardScaler`
4. Кластеризация через **K-Means** (k=5, random_state=42)
5. Семантическая интерпретация центроидов

**5 типов кластеров:**

| ID | Название | Признаки |
|----|----------|----------|
| 0 | Будни (норма) | Два пика (утро/вечер), средний объем |
| 1 | Выходные/Праздники | Сглаженный профиль, низкий утренний пик |
| 2 | Аномальный спад | Объем ниже 20-го перцентиля |
| 3 | Аномальный всплеск | Объем выше 80-го перцентиля |
| 4 | Технический сбой | Странная форма профиля (нули в середине дня) |

**Визуализация:** `cluster_profiles.png` — 5 цветных линий суточных профилей.

### 3. Детекторы аномалий (`detect_daily_anomalies`)

#### 3.1. Детектор целостности
```python
if hours_cnt < 24:
    # Неполные сутки — признак сбоя оборудования
```
**Порог:** < 24 часов в сутках  
**Уровень:** Критический

#### 3.2. Детектор залипания датчика (Flatline)
```python
if max_consec >= 3:  # 3+ часа одинаковых значений > 10 авт./ч
```
**Логика:** Поиск последовательных одинаковых значений интенсивности.  
**Уровень:** Критический

#### 3.3. Детектор дисбаланса направлений
```python
day_df['dir_ratio'] = vol_direct / vol_total
if dir_ratio > 0.85 or dir_ratio < 0.15:  # 2+ часа
```
**Смысл:** Признак закрытия полосы или реверсивного движения.  
**Уровень:** Высокий

#### 3.4. Детектор сдвига в классе ТС
```python
normal_car_share = (cars_total / vol_total).median()
if abs(day_car_share - normal_car_share) > 0.15:  # > 15 п.п.
```
**Смысл:** Запрет грузовиков, сбой классификатора, массовый выезд одного типа ТС.  
**Уровень:** Высокий

#### 3.5. Детектор экстремального затора
```python
if min_spd < 65 and max_load > 15:
```
**Пороги:** скорость < 65 км/ч И загрузка > 15% (адаптировано под А-134)  
**Уровень:** Критический

#### 3.6. Статистические выбросы (Z-score)
```python
z_vol = 0.6745 * (d_vol - vol_med) / vol_mad
if (z_vol < -2.5 and delta_p <= -20.0) or delta_p <= -40.0:
```
**Метод:** Модифицированный Z-score через MAD (Median Absolute Deviation) — устойчив к выбросам.  
**Группировка:** По `месяц + (выходной/праздник)` — праздники сравниваются с праздниками.  
**Пороги:** ±2.5σ И ±20% отклонения.

**Использование:**

- Тег `(Праздник: Новый год)` в описании аномалии

### 5. Поиск причин в Яндекс (`get_yandex_context`)

**Запрос:** `f"Воронеж {date_str} подъезд к Воронежу"` (без слов "ДТП"/"пробка")

**Двухуровневый fallback:**
1. **Яндекс** (`yandex.ru/search/?text=...&lr=213`) — региональный поиск по Воронежу
2. **DuckDuckGo HTML** (`html.duckduckgo.com/html/`) — если Яндекс вернул капчу

**Возвращает:**
```python
{
    'url': 'https://yandex.ru/search/?text=...',
    'text': '16 сентября 2023 года, в День города...',  # или None
    'source': 'yandex' | 'duckduckgo' | 'none'
}
```

**Интеграция в отчет:**
- **Excel:** кликабельная гиперссылка "Открыть поиск"
- **JSON:** полный текст сниппетов для анализа

## 🔑 Ключевые решения и обоснования

| Решение | Обоснование |
|---------|-------------|
| MAD вместо std для Z-score | Устойчивость к выбросам в малых выборках |
| Группировка праздник/выходной | Избежание ложных срабатываний на 1 января |
| Порог затора 65 км/ч (не 40) | Адаптация под специфику А-134 (норма 70-80 км/ч) |
| K-Means с k=5 | Баланс между детализацией и интерпретируемостью |
| Fallback на DuckDuckGo | Яндекс часто блокирует автоматические запросы |
| Запрос без слов "ДТП"/"пробка" | Поиск ремонтов, крестных ходов, велозаездов |
| JSON для контекста новостей | Excel плох для длинных текстов |

## 📈 Метрики качества

- **Покрытие архива:** 3 года × 12 месяцев × ~30 дней × 24 часа = ~26 000 записей
- **Время обработки:** ~2-5 минут на полном архиве (зависит от скорости Яндекс)
- **Точность детекции:** все ручные аномалии (20.07.25, 25.10-07.11.25, 24.11.24, 18.07.24, 20.09.23) найдены автоматически
